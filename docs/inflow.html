THE PROTOCOL, AND WHY IT MATTERS THAT IT IS NOT OURS

DISCOVERY · A2A v1.0 An Agent Card, at a well-known path A JSON manifest at /.well-known/agent-card.json declaring identity, endpoint, skills and how to authenticate. Linux Foundation, 150+ organisations — AWS, Cisco, Google, IBM, Microsoft, Salesforce, SAP, ServiceNow PAYMENT · x402 OVER A2A The spec already covers this exact case A task in state: "input-required" with x402.payment.required in the message metadata. Our 202 is an A2A task waiting; our 402 is that metadata. We did not invent a protocol — we implemented one

AND THIS IS WHY IT IS A LAYER, NOT A FEATURE

THE COUNTERS MULTIPLY Koe will not be the only one Once agents are customers, every panel company, every jobs board, every research marketplace grows an agent front door. They all speak A2A, because that is the only way an agent that never heard of them can arrive.
THE PERSON DOES NOT One router, not one inbox each A person cannot hold an account, a policy and a notification stream per platform. The Agent Card belongs to them, not to a site — so whoever discovers them, the request lands in the same place.
WHAT THAT MAKES POSSIBLE Allocation, across all of it The junk is handled without her. Nothing good is missed because it arrived on the platform she was not watching. And only the part that genuinely needs a person is filtered through — to a wallet that already exists.
Why a standard, and not something of ours. A counter only works if an agent that has never heard of us can use it. If the way to ask is ours, the market is ours to lose — and no agent builder would spend a day learning it. A2A's card is read the same way whoever published it, and x402 rides on the same transport, so the only thing left for us to be good at is the decision.
